/goal

Pamięć intencji w konkretnej rozmowie. Mówi agentowi, dokąd ma dojść i pozwala pracować długo.

  • Trzyma cel aktywny między kolejnymi turami
  • Możesz go pauzować, edytować i wznawiać
  • Nie tworzy sam niezależnego review ani dowodu PASS

⟳

Agent harness

Maszyna wykonawcza zapisana w repo. Mówi agentom, jak zbudować, sprawdzić i udowodnić zmianę.

  • Osobny worktree i twardy zakres plików
  • Writer nie może sam wystawić sobie PASS
  • Stan i dowody przeżyją zmianę chatu albo modelu
Najlepsze użycie razem /goal Dostarcz feature X jako PR. Wykonaj przez agent-harness i zakończ dopiero na niezależnym PASSED.
01 / IZOLACJA

Nie dotyka Twojego brudnego checkoutu

Każdy task dostaje własny branch i worktree. Sibling murmur-server jest przypięty do jednego, konkretnego SHA.

../.murmur-agent-tasks/<id>/meetnotes
02 / SANDBOX

Test nie łazi po komputerze

Stałe środowisko bez tokenów, Cargo offline, prywatny target. Internet wyłączony; UI dostaje tylko loopback.

macOS Seatbelt · private HOME · no egress
03 / REVIEW

Inny model wydaje werdykt

Domyślnie Claude pisze → Codex sprawdza. Ryzykowne zmiany dostają dodatkowy lock/egress/protocol review.

fresh session ≠ writer session
04 / BOUNDS

Pętla ma hamulec

Domyślnie najwyżej dwie rundy napraw. Jeśli nadal jest źle, task kończy się jawnie jako FAILED albo BLOCKED.

max_repair_rounds = 2
05 / DOWÓD

PASS dotyczy jednego diffu

Zmiana po review unieważnia wynik. Hash obejmuje kontrakt, diff, testy, logi, sesje reviewerów i commit receipt.

development-attestation-v2
06 / EVAL

Mierzymy też samych agentów

Ukryte syntetyczne zadania wykrywają false-green, wyjście poza scope, timeouty i obchodzenie guardów.

pass@1 · false-green · scope-fail
