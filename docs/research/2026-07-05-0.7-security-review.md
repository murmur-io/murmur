# Murmur 0.7.0 — Consolidated Security Verdict

## (1) OVERALL VERDICT: **GO**

All five dimension audits returned **PASS**. Across the entire set there are **zero CRITICAL, zero HIGH, and zero findings flagged `blocks_release: true`**. The most severe residual is MINOR — every one is either a defense-in-depth hardening item, a documented-honest-scope limitation, or a pre-existing metadata issue not introduced by 0.7.0. The load-bearing security invariants that gate this release are all independently confirmed intact:

- **E2EE sharing:** L never reaches the server (URL-fragment + `deny_unknown_fields` + two independent HKDF branches); Mode-B HPKE is sender-authenticated + non-replayable + TOFU-hard-block; sealed content is un-shareable while locked (gate-first, no TOCTOU); server is a content-free relay with a correct fetch gate.
- **Lock model:** verify-before-destroy holds across every new sealed artifact (segments/timeline/manual_notes/documents/audio); semantic index (#176/#177) purges-on-seal and never embeds sealed plaintext; dossier/Ask/MCP/tools all route the live unlocked set.
- **Cloud egress:** single consent-gated + `RedactingProvider`-wrapped choke point; #171 `vault_titles` leak closed and guarded by a coverage test; mid-session revoke is effective on the next call (fail-closed).
- **Secrets/startup:** all `MURMUR_DEV_*` hatches compile out in release (no `[profile.release]` debug-assertions override); account-MK is user-presence + WhenUnlockedThisDeviceOnly + non-syncable; the v0.3.1 no-hard-crash-on-keychain/DB-failure startup guarantee is preserved; no secret/PII logging.
- **Supply chain / FFI:** vendored `argon2.js` is sha256-pinned + enforced in CI; new E2EE crypto deps are permissive-licensed and covered by `cargo audit` + `cargo deny` in `scripts/ci.sh`; macOS FFI is crash-safe C-func-only (the biometric path moved off `LAContext`/`msg_send` to the keychain user-presence ACL — the `NSScreen.isCaptured`-class selector-abort risk is structurally absent).

**Nothing must change before cutting 0.7.0.** Ship it, then work the fast-follow backlog below.

## (3) Must-fix vs fast-follow

### Must-fix before cutting 0.7.0 (release-blockers)
**None.** No finding blocks the cut. The release is security-clean to ship.

### Fast-follow (post-release OK) — recommended priority order
1. **#1 — Wrap the retained Mode-B NK under the account MK/folder CK** (top hardening item; closes the one deviation from the "CK protects even while DB open" invariant; additive migration).
2. **#2 — Backend-mask sealed-meeting metadata in `list_meetings`** (moves the Library lock gate from FE-discipline to code; the highest-value lock-model hardening, pre-existing).
3. **#3 — Onboarding/consent copy for name-masking scope** (and/or auto-fetch the NER model on first cloud-consent) — an expectation-setting item; a user reasonably expects names masked by default.
4. **#6 — Add `MURMUR_DEV_ACCOUNT_MK` to `NEVER_INHERIT_ENV`** (one-line consistency fix).
5. **#4 / #5 — Sharing robustness** (griefing download-count + stranded-accept reversibility).
6. **#7 — Server CI supply-chain gate** (`cargo-audit` + `cargo-deny` + `deny.toml`; on the server's own release cadence).
7. **#8 / #9 / #10 / #11 — Cleanups** (drop unused `objc2-local-authentication`; drop the share-window title from logs; remove the `passwordProof` placeholder; optional `/challenge` rate-limit).

## (4) Honest residue — verifiable ONLY on a signed build / real Mac

These are **not gaps in the audit** — they are the class of behavior that headless static + unit review structurally cannot prove. None is a reason to hold the cut, but the release is only *fully* validated once these are checked on the **notarized universal DMG on a real Mac** (a green `cargo test --lib` / `ng build` is not proof here):

- **Touch ID / biometric gates.** The account-MK read (`keychain.rs:dp_biometric_read`, user-presence ACL) and the folder KEK unwrap in `unlock_folder`/`unlock_meeting` only *truly* prompt + gate on a stable-signature signed build. On dev/unsigned, biometrics degrade to `Ok(true)` — so accept-share write-gating, session unlock, and MK caching (#196) need a signed-build pass.
- **Lock-at-rest round-trip.** Seal → re-lock → unlock byte-identical restore on a *real* SQLCipher-encrypted DB with the *keychain* DEK (not the `MURMUR_DEV_DEK` hatch), including the new sealed artifacts (segments/timeline/manual_notes/documents/audio `.enc`).
- **Password-link viewer in real WKWebView + browsers.** The share viewer's `argon2.js` (hash-wasm) Argon2id KDF must compile + run under the viewer CSP (`'wasm-unsafe-eval'`) and correctly derive `KEK_link` to decrypt in the actual notarized server-served page and mainstream browsers — including confirming the server-ignored `passwordProof` path stays inert.
- **Screen-share auto-relock.** `relock_all_inner` firing on a genuine Zoom/Meet/Teams or browser-tab share via `CGWindowListCopyWindowInfo` detection — cannot be exercised headless; needs a live share on a real Mac.
- **Packaged-render CSP (T4 regression class).** Confirm the notarized WKWebView applies Angular's runtime component `<style>` nodes (i.e. `dangerousDisableAssetCspModification: ["style-src"]` still holds and no new `style-src` nonce/hash crept in) — a green `ng build` never reproduces this; verify in the real `.dmg`.

Report all four as "verified on the signed 0.7.0 build" before publishing the GitHub release, but they do **not** gate the GO decision — the code-level security posture is clean.
