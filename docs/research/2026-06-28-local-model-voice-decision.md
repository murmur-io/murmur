# Decision: on-device reasoning brain + voice-trigger stack (Phases 3 & 7)

## TL;DR / Verdict (decision-ready, verifier-corrected)

- **Runtime:** **`mistral.rs`** Rust crate — in-process, Metal, GGUF, **native tool-calling with grammar enforcement + strict-schema mode**, LoRA, Qwen3/GLM/DeepSeek, MIT, v0.8.23 (2026-06-25). Confirmed real (not an Ollama wrapper). Fallback: **`llama-cpp-2`** (utilityai) — lowest-novelty, same ggml/Metal family as our shipped whisper.cpp, GBNF grammar. Both keep everything in-process — satisfies the "no Ollama runtime dependency" constraint.
- **Model:** a **current dense ~14–30B** instruct model, **PINNED AT SPIKE TIME, not hardcoded.** Do NOT bake in "Qwen3-32B" — the verifier found the BFCL number that named it was misattributed (a Qwen3-VL-Thinking row), the live BFCL leader is GLM-4.5 (an un-bundleable 106B/355B MoE), and newer bundleable families (Qwen3.5/3.6-27B dense, etc.) now sit above plain Qwen3-32B. **Default to a ~14B-class dense** model (RAM co-residency with the ~3GB whisper large-v3); offer a ~27–32B opt-in **gated on detected RAM** (32B Q4 ≈ 20GB → wants 48GB; 32GB is "a knife's edge"). **Avoid MoE** for tool loops (documented endless-loop failure) and **avoid reasoning-distill** (R1-Distill emits `<think>`, pollutes structured output). **Download-on-first-run** (like whisper) — never ship 9–20GB in the DMG; bundle the *runtime*, not the weights.
- **Reliability lever (best-evidenced claim in the whole research):** **constrained/grammar decoding, NOT fine-tuning.** SLOT/XGrammar show grammar-alone ≈92–94% schema validity; it beats SFT-alone on *shape*. **Use "reason-then-constrain" (CRANE):** let the model reason freely for the *planning* job, switch the sampler to the grammar only for the final structured block — constraining too early measurably hurts reasoning. Jobs **(b) voice→tool-call** and **(c) NER** are extraction → constrain cleanly; job **(a) context-planning** is reasoning → reason free, then constrain.
- **Name-redaction (job c):** use **GLiNER** (zero-shot NER, DeBERTa, ~few-hundred-MB, ONNX/int8, multilingual, Apache-2.0) via **`gline-rs`** — non-generative, the right tool, and it closes the load-bearing name-redaction gap (`redact.rs:5-6` "Personal NAMES … NOT redacted here"). Caveat: it rides `ort`, which is NOT in our lockfile (sherpa bundles its own ORT) → a **second onnxruntime** in the bundle; Polish NER recall on noisy ASR is **unproven** → spike both.
- **Fine-tune: DEFER.** Stand up the **flywheel correction-log table NOW** (voice-cmd → planner-output → accepted/edited, `owner_id`-tagged, SQLite) — costs nothing, and is the only thing that makes a later LoRA possible. Dataset sizes are small (100–300/intent, 200–500 extraction; "200 curated > 2000 sloppy"; <1k examples LoRA beats full FT). Train later via **MLX-LM QLoRA on the dev Mac** (7B on 16GB, ~90min/5k-ex M2 Max) → fuse → GGUF → load in mistral.rs. Trigger to fine-tune: spike shows JSON is *valid* (grammar works) but the model picks the *wrong tool/args* or mangles Polish register — i.e. a *content* gap, which is the only thing constrained decoding can't fix.

- **Voice trigger ("Hej Claude / Claudku"):** **build the text-transcript path, NOT a dedicated wake-word engine.** All three engines are blocked for Polish/product use (verifier-confirmed against primary sources): sherpa-onnx KWS = **no Polish model**; openWakeWord = **CC-BY-NC pretrained + English-only even for custom training**; Porcupine = **commercial per-device + no standard Polish**. The text path **reuses ~60% of existing infra** and is the only one that handles code-switched PL/EN "Claudku".

## What we already have (grounded — this is mostly an evolution, not greenfield)

- **`complete(system, user) -> Result<String>` provider seam** (`summarize/provider.rs:46`) = exactly where a 4th in-process `LocalLlmProvider`/`Planner` plugs in. Cloud providers are wrapped in `RedactingProvider` behind a fail-closed consent gate (`summarize/mod.rs:47-97`); the local planner is **upstream of** the firewall (it *feeds* redaction) — zero egress, privacy-positive.
- **Two in-process ML runtimes already statically linked:** whisper.cpp via `whisper-rs 0.16` (Metal) + a static onnxruntime via `sherpa-onnx 1.13` (diarization). Adding mistral.rs is the same *shape* of work; `build.rs` already orchestrates native glue. (`ort`/`llama`/`mistralrs`/`candle` are NOT yet in Cargo.toml/lock — each is a new native runtime + the user's no-new-dep approval gate + an unmeasured bundle-size delta.)
- **Download-on-first-run is the established pattern** — models live in `~/Library/Application Support/MeetNotes/models`, fetched once (`transcribe/model.rs:56-85`). A GGUF LLM follows it verbatim.
- **Live ASR loop already runs DURING recording:** `transcribe/live.rs:34-103` runs a *second* Whisper context over the mic tail every 3s and emits `murmur://live-caption` (spawned in `start_recording`, `commands.rs:239`, read-only, self-terminating). **This is the exact seam the in-meeting wake trigger plugs into** — no new capture path.
- **A text wake-phrase matcher already ships** (`audio/listener.rs:31-43`, EN+PL, unit-tested) — but it's literal `String::contains` and wired for *start-recording* (disabled while recording, `commands.rs:3479`). Evolve it: fuzzy/phonetic + in-meeting.
- **`whisper-rs 0.16` exposes `set_initial_prompt`** (`whisper_params.rs:812`), currently UNUSED on the live path — the cheap proper-noun-bias lever to make Whisper emit "Claude/Claudku" consistently.
- **Brittle structured output today** = "parse-and-pray": `reply.find('{')` + `serde_json` in `graph.rs`/`timeline.rs`. Grammar-constrained decoding eliminates exactly this failure.

## Voice-trigger design (Phase 7)

Two-stage, precision-over-recall:
1. **Stage 1 (cheap, high-recall):** a dedicated **tiny/small** Whisper context over the live mic stream (NOT large-v3 — latency), biased via `set_initial_prompt("Hej Claude, Claudku")`, matched by a **fuzzy + phonetic** matcher (normalized edit-distance + Polish→ASCII fold; anchor on the distinct "Claudku", not the common "hej"), requiring an **utterance boundary** (VAD pause) before the wake token.
2. **Delimit** the command utterance to the next VAD silence (sherpa `VoiceActivityDetector`, ~700ms).
3. **Stage 2 (high-precision):** re-transcribe *just that span* at the **Accurate beam profile** (`whisper.rs:220`) — confirms the wake + extracts the command. Discards stage-1 false positives.
4. **Soft visible confirmation** ("⚡ Heard: research X — running, cancel ↩", 2–3s undo) — the cheapest, most reliable false-accept backstop for a meeting context.
5. **Intent parse → tool-call JSON** via the local brain + constrained decoding. Detection/parse = local/zero-egress; execution may egress (deliberate command, through the firewall). Result lands async (recording never pauses) + woven into the note's "Assistant actions".

The **one genuinely uncertain piece** = fuzzy/phonetic matching of a foreign proper noun in Polish — and it's **fully headless-testable** (RED-before-GREEN on a corpus of real Whisper mis-transcriptions of "Claudku": fires on the variant set, silent on a held-out normal-meeting set). The hit-rate of prompt-biased Whisper on real Polish speech is **real-Mac-only**.

## The spikes that gate Phases 3 & 7 (real-Mac, unprovable in CI)

1. **Model/runtime spike (Phase 3 gate):** download 2–3 *current* dense candidates (a ~14B and a ~27–32B, **whatever's current + a GGUF arch mistral.rs actually parses** — note Qwen3.5 GGUF currently panics, mistral.rs issue #2125, and it *panics* rather than degrading → collides with our "never hard-crash on startup" rule). Run mistral.rs in-process with strict-schema on, against ~20 fixtures across jobs (a)(b)(c). **Measure:** schema-valid-JSON rate (target ~100% with grammar), Polish-name recall, tok/s, **resident RAM next to a loaded whisper large-v3** (the co-residency worry).
2. **GLiNER spike (parallel):** multilingual GLiNER on real Polish transcripts → name recall + 2nd-onnxruntime bundle-size delta.
3. **Voice matcher spike (Phase 7, headless):** the fuzzy/phonetic `wake` module on a mis-transcription corpus. + a real-Mac `set_initial_prompt` recording test (say "Claudku" in a Polish sentence 20×; measure token survival).
